# 方向  
明确差距是追赶的第一步。你目前的核心优势是底层系统能力，而目标岗位需要你将这种能力应用到AI领域。具体来说，你需要补充的知识点主要有：

AI推理框架：如vLLM、SGLang、TensorRT-LLM等，需要熟悉其核心原理（如PagedAttention、Continuous Batching）。

GPU编程：掌握CUDA基础，了解如何编写和优化GPU算子。

模型量化与优化：了解量化、剪枝等技术，以降低模型部署成本。


如何高效追赶，缩小差距？
不要试图从头学习AI理论，而应该以工程实践为导向，快速将你的系统能力“嫁接”到AI推理上。

第一阶段（1-2个月）：跑通流程，建立体感

在本地或云服务器上，部署一个开源模型（如Qwen），使用vLLM等框架完成一次完整的推理调用。

亲身体验PagedAttention、Continuous Batching等机制如何影响显存占用和吞吐量。

第二阶段（2-3个月）：深入源码，理解原理

阅读vLLM的核心源码，重点理解其内存管理机制，这与你的操作系统知识直接相关。

学习CUDA编程，尝试编写一个简单的矩阵乘法算子，理解GPU的并行计算模式。

第三阶段（持续）：项目驱动，积累经验

将你的学习过程整理成项目，发布在GitHub上。一个包含“基于vLLM的推理服务优化”或“自定义CUDA算子实现”的仓库，是简历上最有力的证明。

精准搜索：在招聘平台使用“AI Infra”、“推理引擎”、“模型部署 C++”、“AI算子开发”等关键词，而非“AI推理部署”。

# 一个skill示例说明

假设你未来在工作中，总结出了一套“排查推理服务GPU利用率低”的标准流程。你可以把它封装成一个Skill：

gpu-utilization-troubleshooting/SKILL.md

markdown文件
---
name: gpu-utilization-troubleshooting
description: 当推理服务GPU利用率低于预期（如<50%）时，按此标准流程进行排查。
---

# GPU利用率排查标准流程

## 第一步：收集基础指标
- 运行 `nvidia-smi dmon -s pucvmet -d 1` 观察GPU使用率波动。
- 检查推理服务的QPS（每秒查询数）和P99延迟。

## 第二步：检查请求批次（Batching）
- 如果QPS很低，GPU在“等饭吃”。检查请求队列长度。
- 如果队列为空，瓶颈可能在网络或前端，而非GPU。

## 第三步：检查显存与计算瓶颈
- 运行 `nsys profile` 或 `nvprof` 分析kernel耗时。
- 如果kernel耗时占比低，瓶颈在数据搬运（CPU<->GPU）。

## 第四步：检查模型量化与算子
- 确认模型是否已使用INT8/FP16量化。
- 检查是否有未融合的自定义算子拖慢速度。

这样，当你之后使用AI工具时，只需说“用GPU利用率排查技能来分析一下这个问题”，AI就会自动加载这套你精心设计的流程，按部就班地帮你排查。你不仅是在使用AI，更是在“训练”AI按你的专家方式来工作。

# 关于大模型和agent的理解
DeepSeek 软件本身不是一个 Agent，它更像一个“超级大脑”，而 Agent 是把这个大脑装上“手脚”和“记忆”后，能自主干活的系统。
1. DeepSeek 软件（App/网页版）是什么？
它是大语言模型（LLM）的对话应用。你输入文字，它生成文字回复。它具备很强的理解、推理、生成能力，但没有自主行动能力。它不会主动去搜索网页、调用API、操作你的电脑、记住跨会话的长期历史（除非你手动贴上下文）。它只是“一问一答”的被动响应。
2. Agent 是什么？
Agent（智能体）是一个能自主规划、调用工具、执行多步任务、并根据结果调整策略的系统。一个典型的 Agent 包含：

大脑：LLM（比如 DeepSeek、GPT）

规划：把大任务拆成小步骤，决定下一步做什么

工具：调用搜索引擎、代码执行器、数据库、API等

记忆：短期/长期存储上下文和结果

循环：执行→观察结果→再决策→再执行，直到任务完成

比如你让 Agent “帮我查一下西安明天的天气，然后根据天气推荐穿什么”，它会：

规划：先查天气，再推荐穿搭

调用天气API

拿到结果后，再让 LLM 生成穿搭建议

返回最终答案

这个过程 DeepSeek 聊天窗口做不到，它只会直接回答“我不知道实时天气，建议你查天气预报”。


----
更准确地说：DeepSeek 软件是“基于 LLM 构建的对话产品”，LLM 只是它背后的核心引擎。

你未来要做的推理部署，很大一部分工作量就是专门为 Agent 的“多轮对话 + 工具调用”做底层优化：

KV Cache 的复用：Agent 的对话非常长（包含历史对话、工具返回结果、规划过程），每次对话都要重新计算上下文会慢死。你的工作就是让推理引擎能高效复用 KV Cache，让长对话也能低延迟响应。

高并发：一个 Agent 可能同时服务几千个用户，每个用户都在进行多轮对话。这就需要你用 C++ 和高并发功底，设计出能扛住海量请求的推理服务。

流式输出：Agent 的对话必须是“打字机”式的流式返回，这要求推理引擎支持 Continuous Batching（连续批处理），这也是 vLLM 等框架的核心卖点。

一句话总结：Agent 的“全自动执行”是它的大脑和手脚，而“对话”是它的嘴巴和耳朵。两者缺一不可。你未来的工作，就是让这个“大脑和嘴巴”在底层跑得又快又稳。


# 华为E9000H刀片服务器
E9000H系列主要有两种形态，规格差异明显：

特性	E9000H-4 (4U)	E9000H-2 (2U)
处理器	鲲鹏架构	鲲鹏架构
内存	16 x 32GB DDR4（每单板）	16 x 32GB DDR4（每单板）
网络接口	2 x (4 x 10GE/25GE)（每单板）	2 x (4 x 10GE/25GE)（每单板）
整机功耗	2400W / 3000W	490W / 550W
重量	60 kg	27.8 kg
支持最大用户数	20K	10K
最大吞吐量	20 Gbps	10 Gbps

鲲鹏+昇腾生态：E9000H采用鲲鹏处理器，而华为的AI加速卡（昇腾）也属于同一技术体系。这意味着你在学习AI推理部署时，昇腾生态（CANN、Omni-Infer等） 是一个值得关注的方向，它和NVIDIA的CUDA生态是并行的两条赛道。

安装的系统： openEuler（欧拉）和 EulerOS 是华为主推的操作系统

模型部署：国产化系统：如果涉及信创或华为生态，openEuler是理想选择，尤其适合与鲲鹏/昇腾硬件搭配

昇腾和 GPU 的关系：昇腾不是 GPU，而是 NPU（Neural Processing Unit，神经网络处理器）或更广泛的 AI 加速器（AI Accelerator）。它在 AI 计算领域扮演与 GPU 相同的角色（提供算力），但架构不同（专用架构 vs 通用并行架构）。

----
鲲鹏（CPU）：像“项目经理”
定位：通用计算。

特点：核心数相对较少（比如几十个核），单核能力强。它擅长逻辑控制、操作系统调度、网络通信、数据预处理。

在 AI 里的作用：它不负责算大模型那海量的矩阵乘法，而是负责把数据准备好，然后指挥昇腾（NPU）：“嘿，这批数据交给你算了！”

⚡ 昇腾（NPU）：像“数学计算器”
定位：AI 专用加速。

特点：核心数极多（几千个 AI Core），专为矩阵乘法和深度学习算子设计。在算大模型这种高度重复的庞大计算时，它比 CPU 快几千倍。

为什么叫 NPU 而不是 GPU：GPU（如 N卡）最初是画图用的，后来发现算 AI 也很强，属于“通用并行计算”。而 NPU（如昇腾）从生下来第一天，架构就是为了神经网络设计的，属于“专用定制”。  

---

 这对你的转型意味着什么？（非常关键）
你未来找 AI Infra 工作，在简历上一定要分清楚这两条技术栈：

NVIDIA 路线：学 CUDA、TensorRT、vLLM 原生版。这是大多数互联网公司和云厂商在用的。

华为昇腾路线：学 CANN、昇腾算子开发、MindSpore、vLLM 昇腾版。这是信创、政企、运营商（比如你以前做的 5GC）在大力推的。

你的优势在哪里？
你过去 8 年在 5GC 核心网（PCRF/Gx）的经验，大概率接触过华为的硬件。如果你能把“C++ + 操作系统 + 华为硬件生态”三者结合起来，去搞“**昇腾 NPU 上的推理部署**”，那你在西安（华为西研所所在地）或者北京的信创/政企赛道，就是非常稀缺的人才。

一句话总结：鲲鹏是发号施令的“大脑（CPU）”，昇腾是埋头算矩阵的“AI 计算器（NPU）”，它们配合起来，就是华为全栈的计算底座。 这也再次印证了之前说的：AI Infra 不只有 CUDA 一条路，昇腾生态同样广阔。继续加油！
